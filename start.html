1はじめに：2つのコース

このガイドは私用PC・個人のアカウントで、練習用の題材を使って試すことを前提にしています。

A. しっかりコース 有料プラン

  • Claude Code を使い、デモと同じTODOアプリを実際に作る
  • Plan mode・SubAgent・Skill も体験できる
  • 所要時間：1.5〜2時間（準備30分＋作業）
  • 必要なもの：Claude の Pro 以上のプラン

B. お試しコース 無料

  • インストール不要。ブラウザのチャットで試す
  • 要件定義書・テスト仕様書づくりとレビューを体験
  • 所要時間：30分
  • 必要なもの：Claude の無料アカウント

どちらのコースも、まず 2. チェックリスト を確認してください。B コースの人は 3〜5 を飛ばして 6 へ進めます。チェックした内容はこのブラウザに保存されます。

3準備：Claude Code を入れる A コース

ターミナル（黒い画面）に、コマンドを貼り付けて実行します。手順は 2026年11月時点の公式ドキュメントに基づいています。

ターミナルが苦手な人は、画面で操作できる デスクトップアプリ 版でも同じことができます。その場合は ①② を飛ばし、アプリでログインしてから ③ のフォルダを開いてください。

① ターミナルを開く

Spotlight（⌘+Space）で「ターミナル」と入力して開きます。

スタートメニューで「PowerShell」と入力して開きます（管理者として実行する必要はありません）。画面に PS C:\ と表示されていれば PowerShell です。

② インストールして確認する

ターミナルに貼り付けて Enter
curl -fsSL https://claude.ai/install.sh | bash
PowerShell に貼り付けて Enter
irm https://claude.ai/install.ps1 | iex

途中経過は表示されません。終わったらターミナルを一度閉じて開き直し、次のコマンドでバージョン番号が出れば成功です。

確認
claude --version

③ 練習用フォルダを作って起動する

ターミナル
mkdir -p ~/ai-practice/team-todo
cd ~/ai-practice/team-todo
git init
claude

git が無いと表示されたら、画面の案内に従って開発者ツールをインストールしてから、もう一度実行します。

PowerShell
mkdir $HOME\ai-practice\team-todo
cd $HOME\ai-practice\team-todo
git init
claude

git が見つからないと表示されたら、Git for Windows を入れてからターミナルを開き直します。

初回はブラウザが開くので、個人のアカウントでログインします。「このフォルダを信頼しますか」と聞かれたら、練習用フォルダであることを確かめてから許可します。

④ 最初の一言を送る

Claude Code に送る
こんにちは。このフォルダは練習用の空のプロジェクトです。これから一緒にTODOアプリを作ります。返答と作る文書は日本語でお願いします。

覚えておく操作

操作内容
EscAIの作業をその場で止める
Shift+Tab（数回）モードの切り替え。画面下に ⏸ plan mode on と出れば Plan mode
/rewind または Esc 2回（入力欄が空のとき）前の状態に巻き戻す（AIが編集したファイルと会話）
/exit終了。claude --continue で続きから再開できる

4ハンズオン：TODOアプリを作る A コース

デモと同じ流れです。各ステップで指示文をコピーして送り、レビューのチェックを付けてから次へ進みます。デモと違い、AIの返事は毎回変わります。

💡 各ステップの終わりに「ここまでの変更をコミットして」と頼んでおくと、失敗しても戻せます。

STEP 1要件定義 （デモのフェーズ1）

指示文
チームで使えるシンプルなTODO管理アプリを作りたいです。
【目的】チーム内のタスクの抜け漏れを防ぎたい
【前提・制約】ブラウザだけで動く（サーバーなし）／データは各自のブラウザに保存／タスクに期限を設定したい
【出力】docs/requirements.md に要件定義書を作成。機能要件はID（FR-01〜）付きの表で
不明点があれば、作成する前に質問してください。推測で決めた点は「仮定」と明記してください。

AIから質問が来たら、自分の考えで答えてください。答えに正解はありません。

STEP 2実装計画 Plan mode （デモのフェーズ1の最後）

Shift+Tab を何回か押し、画面下に ⏸ plan mode on と出たら、次の指示を送ります。この間、AIはファイルを変更しません。

指示文（Plan mode で送る）
docs/requirements.md をもとに実装計画を立ててください。
・HTML / CSS / JavaScript だけで作る（ライブラリ不要、index.html をダブルクリックで開ける形）
・作業を2つに分け、サブエージェント2体で並列に実装する前提にする
・並列化の前に決める共通ルール（データの形・一覧の並び順・どのファイルを誰が担当するか）も計画に含める

STEP 3並列実装 SubAgent （デモのフェーズ2・3）

計画を承認したら、次の指示を送ります（Plan mode が解除されていなければ Shift+Tab で戻します）。

指示文
計画どおり実装してください。
最初に共通ルールを docs/conventions.md に書き、それを渡したうえで、サブエージェント2体で並列に作業してください。
終わったら、レビューしてほしい観点（AIが仮定した点・確認してほしい点）を一覧で示してください。

できあがった index.html をブラウザで開いて、実際に触ってみましょう（フォルダを開いてダブルクリック）。

STEP 4テスト仕様書 （デモのフェーズ4）

指示文
docs/requirements.md をもとに、docs/test-spec.md にテスト仕様書を作成してください。
・正常系と異常系（未入力・空白だけの入力など）を含める
・各ケースに、対応する要件ID・手順・期待結果・「1回目」「2回目」の結果欄を付ける
・対象外にした観点があれば、理由とともに書く

STEP 5打鍵テスト（ここは自分の手で） （デモのフェーズ5）

デモではAIが操作しましたが、ここでは自分でテスト仕様書の手順どおりにブラウザを操作し、結果欄に OK / NG を記入します（記入をAIに頼んでも構いません）。

NGが1件も出なかったら：要件を1つ追加して、STEP 1〜5 をもう一周してみましょう。おすすめは「一覧を期限が近い順に並べ替える」機能です。デモでエージェントBが勝手に入れた改善を、今度は人間が決めた要件として正式に追加します。

STEP 6修正・回帰テスト （デモのフェーズ6）

指示文（○○ の部分を書き換える）
テスト仕様書の TC-○○ がNGでした。
手順：（実際にやった操作）
期待結果：（仕様書の期待結果）
実際の結果：（起きたこと）
原因を調べて修正し、変更差分を見せてください。修正後に再テストすべきケースも教えてください。

🎉 お疲れさまでした！ ここまでで、デモと同じ流れを本物のAIで一通り回せました。

5Skill を作って使い回す Skill A コース

ハンズオン中に何度も出てきた「レビュー依頼」を、Skill（AIが必要なときに読み込む手順書）にして、毎回同じ型で出してもらえるようにします。

① Skill のファイルを置く

下の スターターキット から SKILL.md をダウンロードし、練習用フォルダの中の次の場所に置きます（フォルダが無ければ作ります）。

置き場所
team-todo/.claude/skills/review-request/SKILL.md

ファイルを置くのもAIに頼めます：「.claude/skills/review-request/SKILL.md を作って、次の内容を書いて」と頼み、内容を貼り付けます。

② 呼び出す

Claude Code を一度終了（/exit）して起動し直し、入力欄に次のように入力します。

入力
/review-request docs/test-spec.md

6無料で試すコース B コース

インストールせず、ブラウザで claude.ai に個人のアカウントでログインして試します。「書く作業をAIに任せて、人間がレビューする」部分を体験できます。

STEP 1要件定義書を作ってもらう

チャットに送る
チームで使えるシンプルなTODO管理アプリの要件定義書を作ってください。
【目的】チーム内のタスクの抜け漏れを防ぎたい
【前提・制約】ブラウザだけで動く（サーバーなし）／データは各自のブラウザに保存／タスクに期限を設定したい
【出力形式】機能要件はID（FR-01〜）付きの表で
不明点があれば、作成する前に質問してください。推測で決めた点は「仮定」と明記してください。

STEP 2テスト仕様書を作ってもらう

チャットに送る
この要件定義書をもとに、テスト仕様書を表で作成してください。
正常系と異常系を含め、各ケースに対応する要件ID・手順・期待結果を付けてください。
テストの対象外にした観点があれば、理由とともに書いてください。

STEP 3（できれば）アプリも作ってもらう

チャットに送る
この要件定義書どおりのアプリを、HTML 1ファイル（CSS と JavaScript も中に含める）で作ってください。

チャット画面にアプリが表示されたら、そのまま触ってテスト仕様書どおりに打鍵してみましょう。表示されない場合は、コードをコピーしてメモ帳などに貼り、index.html という名前で保存してブラウザで開きます。

7困ったときは

claude --version で「見つからない」「認識されません」と出る

インストール直後は、ターミナルを閉じて開き直すと直ることがほとんどです。直らない場合は 公式のトラブルシューティング を確認してください。

Windows で 'irm' is not recognized と出たら CMD を開いています。PowerShell を開き直してください。

ログインで「このプランでは使えない」と言われる

Claude Code は無料プランでは使えません。B コース（6）で試すか、プランを確認してください。

AIが質問せずに作り始めた／思っていたのと違う方向に進んでいる

Esc で止めて、「いったん止めて。作る前に、不明点を質問してください」と伝えます。大きな作業は Plan mode で計画から始めると防げます。

やり直したい・元に戻したい

/rewind（または入力欄が空のときに Esc 2回）で、指示を送る前の状態に戻せます。ただし、コマンドで変更されたファイルや SubAgent の変更は戻せないことがあるので、区切りごとに「コミットして」と頼んでおくのが安全です。

英語で返事が来る

「日本語で答えてください」と伝えます。毎回伝えるのが面倒なら、スターターキットの CLAUDE.md をフォルダに置くと、プロジェクトのルールとして読み込まれます。

「利用上限に達しました」と出た

プランごとに一定時間あたりの利用量に上限があります。表示された時間まで待つと再開できます。

許可を求められたけど、何をするのか分からない

許可せずに「このコマンドは何をするものですか？」と質問してください。分からないまま許可しないことが、いちばんの安全策です。

練習が終わったら？

練習用フォルダは消して構いません。続けない場合は、プランの更新日までに解約を忘れずに。アンインストール方法は 公式ドキュメント の「Uninstall」にあります。
